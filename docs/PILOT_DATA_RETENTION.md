# Datos y retención para piloto — pendiente de acuerdo corporativo

Este documento delimita qué puede manejar el piloto. No establece una política corporativa definitiva de AVGUST.

| Tipo de dato | Uso en el piloto | Almacenamiento | Decisión de retención |
| --- | --- | --- | --- |
| Identidad de participantes | Acceso y autorización | Proveedor de identidad del sitio y membresías por finca | **PENDIENTE DE ACUERDO CORPORATIVO** |
| Contactos de finca | Destinatarios y coordinación | D1 | **PENDIENTE DE ACUERDO CORPORATIVO** |
| Visitas, respuestas, hallazgos y compromisos | Registro técnico del piloto | D1; SQLite independiente en Windows si se usa | **PENDIENTE DE ACUERDO CORPORATIVO** |
| Fotografías | Evidencia técnica asociada a una visita | R2 privado; copia local solo en Windows | **PENDIENTE DE ACUERDO CORPORATIVO** |
| Informes Word/PDF | Entregable descargado por el usuario | Dispositivo de quien descarga; snapshots de informe en D1 | **PENDIENTE DE ACUERDO CORPORATIVO** |
| Respaldos | Recuperación autorizada | Ubicación corporativa restringida definida por AVGUST | **PENDIENTE DE ACUERDO CORPORATIVO** |

## Reglas mínimas durante el piloto

- Introducir solo datos necesarios para validar el flujo.
- No cargar credenciales, información financiera, datos personales sensibles ni evidencia sin autorización.
- Registrar quién autoriza un respaldo y su fecha de corte; no automatizar ni borrar datos remotos durante el piloto.
- La eliminación posterior, duración de conservación, cifrado, responsables y acceso a copias requieren un acuerdo corporativo previo. Hasta entonces no se debe prometer una fecha de eliminación ni un mecanismo de purga.
